## 真机确认的 API（Rhino 9.1.26314.9001）

| API | 真实签名 / 行为 | 注意 |
|---|---|---|
| `Plane.FitPlaneToPoints(points)` | 返回 `(PlaneFitResult, Plane)` **两元组** | 不是 `(bool, Plane, out double)` 三元组；`int(result)==0` 为成功 |
| `Plane.DistanceTo(point)` | 有符号距离 | 偏差取绝对值；实测 `Point3f` 也能传 |
| `mesh.Vertices[i]` | 返回 `Point3f` | Rhino 9 绑定会自动转 `IEnumerable<Point3d>`；显式转 `Point3d` 只为跨版本保险 |
| `Mesh.ClosestPoint` | 存在 | 点到有限网格面时用 |
| `Mesh.Raycast` | **不存在** | 3D sketch 不能直接调它，需另找 |
| `PlaneSurface(plane, Interval, Interval)` | 用 `Interval` 不是数组 | 传 `[w,h]` 会把 plane 当 IntPtr 报错 |
| `doc.Strings.SetString(section,key,value)` | 不是 `SetValue` | 读取用 `GetValue(section,key)` |
| `MeshFace` | 不可 `for` 迭代 | 用 `.A/.B/.C` + `.IsTriangle ? .D` |
| `ObjectAttributes.ColorSource` | `ObjectColorSource.ColorFromObject` | 颜色用 `System.Drawing.Color`（不是 Rhino.Drawing） |
| `doc.Objects.Delete(id, True)` | 可用 | 自检重跑时清理遗留对象 |

## 已知局限（诚实边界）

1. 曲率的"角亏/面积"是离散估计，跨模型尺度不可直接比较，只适合同一模型内的相对筛选。
2. P0 只拟合平面；有机曲面（CurveNetwork/Quad/Toleranced Patch）未做，那是 P3。
3. **`main()` 的交互点击流程仍需真人走查**：`GetObject` 选网格 + `GetString` 输面索引
   在无人值守环境会阻塞；自动化已覆盖它调用的核心函数与 `run_fit()` 执行体，
   但没覆盖"真人点一下鼠标"这一步。
4. 本次验证在**用户当前 Rhino 文档**落地了自检对象（有命名、重跑自动清理），
   不再是纯 headless 临时文档；如需干净文档，手动删 `M2S_SelfTest_*` 即可。
5. 已接入真实扫描网格（猫爪笔筒 STL，150 万面），但**只跑通平面拟合与类型判别**；
   球/圆柱的完整拟合受限于「覆盖角不足」，需区域生长（P1）。
6. **打印朝向评估不是力学仿真**：`python/print_orientation.py` 按面法向与 Z 轴夹角
   统计自支撑/悬垂/朝下底面，并搜索最优摆放朝向；它**不模拟**材料下垂、热变形、
   层间强度。内腔朝下面未必真需要支撑。结论需真人看切片预览确认。
7. **大网格会话稳定性（2026-11-25 16:15 实测崩溃）**：用户当天 14:47 启动的 Rhino
   会话在导入 150 万面 STL、回写彩色子网格后运行 87 分钟时崩溃（CLR FailFast，
   故障模块 .NET `WindowsBase.dll`，详见工作日志）。**纪律**：大网格验证单独开

## 串联链（2026-11-25 09:45 新增）

`python/chain_core.py` 把 NFF 与 m2s 串成完整流水线：

```
网格 → NFF.filter_faces(法向夹角) → m2s.face_curvature/filter(曲率)
     → 两族求交 → fit_plane → deviation → 合格判定
```

**为什么求交**：单靠法向会收进"朝向对但是弯的面"，单靠曲率会收进"平但朝向不对的面"。
交集才是"朝这个方向的一张平面"——AI 分面要的候选。

- 接口：`run_chain(vertices, faces, direction, angle_deg, include_opposite,
  min_angle_deg, k_max, k_min, rms_tolerance, within_tolerance, verbose)`
- 返回：每步中间结果（normal_kept / curvature_kept / candidates / plane / deviation /
  accepted / reason）——便于调试"卡在哪一步"。
- 测试：`tests/test_chain.py` 5 项，加上原 10 项共 **15/15 PASS**。
  测过：顶面筛选、双向模式（两层面不合格）、竖直面、空结果、摘要。
- 坑：平面拟合的约束是**顶点数≥3**不是面数≥3（一个四边形面就有 4 顶点，够拟合）。

### 三个架构问题（真机才暴露）

1. **`chain_core.run_chain` 的大网格不可用**：它对每个面调 `face_curvature`，
   而后者内部又遍历全部面找邻居 → O(n²)。150 万面 ≈ 2.2 万亿次比较，跑不完。
   → 大网格必须走 `stl_chain.py`（全 O(n)）。
2. **「法向命中」≠「一张平面」**：31,735 个近 +Z 面一次性 `fit_plane`，
   拟合法向 `(-0.775, -0.086, 0.626)`，**与 +Z 差 51°**，RMS 0.155，完全不可用。
   同朝向的面在真实件上散落在多处（筒顶、球面、台阶），必须先分区。
   → `segment_core.face_components`（并查集，共享 ≥2 顶点算相邻）。
3. **Rhino 9 没有圆柱/圆锥/圆环拟合 API**：`Cylinder` / `Cone` / `Torus` 的 `Fit*` 全为空，
   只有 `Plane.FitPlaneToPoints` 与 `Sphere.FitSphereToPoints`。
   筒状件的侧壁要么自己实现（已做 Kasa 2D 圆拟合），要么走 NURBS。

### 猫爪笔筒特征分解（2026-11-25 10:40 新增，修正上一版结论）

用户确认实物是**猫爪笔筒**后，`#1–#5` 的定性必须改：它们不是「球面误检碎片」，
而是**猫爪肉垫的球面顶部**——真实特征，只是被**平面**这个错误基元拟合了。
用同一批点分别做平面与球拟合，球拟合全面占优：

| id | 面数 | 平面 RMS | 球 RMS | 平面/球 | 代数 R | 内核 R | 覆盖角 | 判定 |
|---|---|---|---|---|---|---|---|---|
| 0 | 23,198 | 0.001801 | 0.011147 | 0.16 | — | — | — | **平面**（筒口环） |
| 1 | 5,845 | 0.003859 | 0.000336 | **11.5** | 0.0963 | 0.0962 | 31.6° | 球面 |
| 2 | 1,205 | 0.002019 | 0.000822 | **2.5** | 0.1387 | 0.1208 | 35.6° | 球面 |
| 4 | 491 | 0.001274 | 0.000186 | **6.8** | 0.0398 | 0.0396 | 31.5° | 球面 |
| 3 | 714 | 0.003413 | 0.000276 | **12.4** | 0.4371 | 0.1753 | 110.8° | 球面（R 不可信） |
| 5 | 190 | 0.000704 | 0.000061 | **11.5** | 0.0764 | 0.0531 | 174.2° | 球面（解退化） |

**类型判别可靠**：`#0` 的球拟合反而更差（比值 0.16），其余 5 块球拟合好 2.5–12 倍。
判据可直接进流水线：`type = SPHERE if plane_rms / sphere_rms > 2 else PLANE`。
对应脚本 `python/catpaw_fit.py` → `catpaw_result.json`。

**但半径不可靠，两层原因**：

1. **覆盖角太窄**。法向筛只留了每个肉垫朝 +Z 的顶部小片，`#1/#2/#4` 覆盖角仅 31–36°。
   球冠覆盖 < 40° 时半径与球心强耦合，**数据本身定不住**，不是算法能修的。
2. **两块是病态解**。`#3` 的 R=0.437 相对块面积（0.00027）大到不合理，球心已跑到模型外；
   `#5` 覆盖 174°，说明点在球心两侧对称分布——拟合出的是「点云包围球」，不是球冠。

**试过但失败的方法（反面教材）**：`pad_grow.py` 用「全网格顶点到球心的距离直方图」
找球壳峰再重拟合，得到 R=0.10/0.40/0.50/0.62/0.56、覆盖角 94–171°，看起来全 RELIABLE。
**这是假峰**：150 万面的密集网格里任意大球壳都会与筒壁、其他肉垫相交，交面遍布整个球面，
所以「覆盖角」必然接近 180°，band 里 3 万点分散在模型各处而非一片连续曲面。
脚本已标 DEPRECATED，保留以便复现错误。

**正确方向（P1 核心）：面级连通生长**

```
种子块 → BFS 沿共享边扩展 → 只收 |d-R| < tol 且 面法向·径向 > cos45° 的邻面
       → 每轮用生长后的点重拟合 → 直到点数/半径稳定
       → 覆盖角 ≥ 60° 才输出半径，否则只输出类型
```

判据必须是「**一片连通曲面**」，不是「球壳带上的所有点」。

### 面级连通生长（P1 已落地，2026-11-25 11:3x）

`python/connected_growth.py` 按上面判据实现，关键工程点：

1. **邻接用 CSR 顶点倒排**（`vertex -> face` 的 int32 扁平数组，450 万条 ≈ 18 MB），
   不建 450 万条边的 dict；两个面共享 ≥2 顶点才算相邻（共享一条边）。
2. **tol 退火**：窄冠拟合残差很小，但把小残差当 tol 外推到冠边缘会立刻失败
   （R 偏了，误差不在残差里而在外推里）。所以前几轮 tol 放到 0.20·R 让生长启动，
   每轮 ×0.88 收紧，后期交给 3·rms 主导。这是绕过「窄冠外推病态」的工程办法，
   **不是**从数据里推出了额外信息——半径最终仍由生长后的覆盖角定住。
3. **5 条可靠判据**（全过才给半径）：`60° ≤ 覆盖半角 ≤ 120°`、生长倍率 ≥1.2、
   `rms/R ≤0.05`、末 10 轮 R 漂移 ≤2%；种子覆盖半角 >120° 直接判病态、跳过生长。
4. **axis 固定为种子块平均面法向**，覆盖半角才可前后比较。

**合成球冠自检**（带 0.004 径向噪声，`python connected_growth.py --selftest`）：
窄冠 R 偏 1.93% → 生长后 0.08%，覆盖半角 25°→80.1°，面数 1728→5760（57 轮），
未串入不连通的干扰平面，可靠判定生效 → **PASS**。

**真机结果**（150 万面，13.7 s）：

| 块 | 种子面 | 生长后面 | 倍率 | R0 → R（数值单位；括号内 mm） | 覆盖半角 | rms/R | 末10轮漂移 | 判定 |
|---|---|---|---|---|---|---|---|---|
| #1 | 5,845 | 42,246 | ×7.2 | 0.0963 → **0.0991（15.19 mm）** | 32.1° → 89.3° | 0.013 | 0.6% | ✅ 可靠 |

上一轮假峰（10/40/50/62/56 mm）是按**已作废的 ×100** 换算报出来的，数值整体作废，
只保留「方法错误」这个教训。另 3 个失败原因各不相同且都写进结果：#4 是生长过冲（平面/球 RMS 比从
6.84 掉到 1.06，已经不是球面，确实串进了筒壁）；#3/#5 的种子点集本身在球心两侧

**诚实边界**：

1. 两块病态种子的半径仍未知，必须换种子（从肉垫边缘而非顶部法向筛取），属 P2。
2. #4 的过冲说明 `|d-R|<tol` 在筒壁上也近似成立（筒壁到球心距离恰好接近 R），

4. 合成测试只验证算法本身（球冠 + 干扰平面），不等于真实扫描件的全部情形。

### 回写 Rhino 的两个坑

1. **STL 导入器会重排面顺序**：同一批 `face_indices` 在 Python 解析结果与 Rhino Mesh 里
   指向不同三角面（实测质心差 0.26，z 却一致）。→ 不能复用面索引，
   `segment_core` 额外输出 `vertices + local_faces`，Rhino 端**按坐标重建**。
2. **隐藏对象不在 `doc.Objects` 常规枚举里**：`doc.Objects.Show()` 要 id，
   得用 `ObjectEnumeratorSettings()` 并把 `HiddenObjects = True` 才找得到。
