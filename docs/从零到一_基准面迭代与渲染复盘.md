# 从零到一：基准面四版迭代与观测显示复盘

> 本文按反馈重新整理，结合真实迭代过程写成，主线聚焦基准面工具从零到一的四个阶段，以及围绕"看得清"展开的观测显示调参。
> 收益 / ROI 部分不纳入——那需要更扎实的量化支撑，等有真实场景数据再单独成篇。

## 一、为什么先把基准面立起来

动手做功能之前，我们先把"基准面"定义清楚。

在 Rhino 里，基准面不是最终产物，而是一把尺子：它规定输入是什么、输出长什么样、用什么口径判断好坏。用户要的是"在斜面上建一个基准面，让 CPlane 和操作轴对齐，像在顶视图一样建模"——这个意图必须先落成一个明确的几何对象，后面每一次显示调参、交互改动才有对照。

所以从零到一的第一步，不是堆功能，而是先把这把尺子立住：三点定面或拾取平面 → 生成半透明基准面 → 对齐 CPlane 与 Gumball → 保存进 `.3dm`。没有它，后面每一次改动都说不清是进步还是倒退——尤其当结果由模型和视口显示共同决定、又带着调参随机性的时候。

## 二、四个阶段的迭代

### 阶段一｜能跑起来的最小闭环

目标只有一个：**先让它跑通**。

- 确定最小输入契约：三点或拾取一个平面；输出：一个可见的基准面 + 对齐的 CPlane。
- 建立最原始的基准面：一组固定输入 + 一套能自动跑出结果的脚本。
- 通过进程内 Roslyn 把 C# 编译成 `.rhp` 并在真实 Rhino 里加载（本机没有 .NET SDK，这一步本身就是关口）。

这一阶段的价值不在效果，而在把"能不能做"从不确定变成可观察。过程中修掉了几个真 bug：原平面必须在 `SetConstructionPlane` **之前**读取，否则"取消"恢复的是基准面自己。

### 阶段二｜把基准变成一把可复现的尺子

能跑通之后，问题变成："同样的输入，两次结果一样吗？退出后能不能精确还原？"

- 真实文档 **35/35 PASS**：编号子层 `DP_01`、锁定、三处元数据、切换不增对象、退出精确回初始 CPlane 与 6 项全局设置。
- 把散落的判断收敛成可验证的指标：用反射读 Plane、文档字符串、对象属性，而不是"看一眼觉得对"。
- 状态机从"禁止操作"改为"映射为切换"——激活态再新建不再报"已有基准面"，而是切到新面并保留唯一恢复基线。
- 第 5 法向视图：相机垂直于基准面，Top 视图竖直分割，44/44 PASS。

这一阶段之后，基准面才从"能看"升级为"能量"。迭代开始有据可依。

### 阶段三｜场景化：观测显示接进来

基准面稳了，开始往真实使用场景走——也就是"看得清"。

- 最初想 1:1 复刻 Rhino 内置的 `Alias Style`，实测发现它 `ShowIsoCurves=False`、`FrontDiffuse=219`、`Ambient=116`、高曝光，画面一片白。用户明确否掉这条路线："不是让你复刻，是让你把显示变得更好看一点。"
- 于是改成护眼改造：暖绿 / 暖石墨双主题、开等参线、压高光、关构建网格与坐标轴。
- 但过曝的根因还在，直到逐像素采样才定位：`DefaultLighting` 下白色物体的平面必被直射光打到 255，`clip(≥253)` 达 2.3%~9.5%。此前一直在调 `FrontDiffuse` / `ObjectColor`——对带材质对象**完全不生效**，等于白调。

这一阶段是从"实验室基准"走向"真实场景"的关键一跃，也把效果和成本的矛盾摆上台面：为了找到真正有效的参数，做了多轮参数扫描与截图对比。

### 阶段四｜收敛：从能用到好用

最后一版不再追求加东西，而是收口。

- 弃用"复刻 Alias Style"，改走社区共识的 clay / 白模：纯 `AmbientOcclusion` + 地面软阴影 + 轮廓线，`clip` 降到 0.00%。但新的问题又暴露：AO 只有接触遮蔽，没有受光—侧光—背光的梯度，曲面"糊成一片"。
- 查资料确认 `LightingSchema` 是枚举不是 flag，方向光与 AO 只能二选一；Monochrome 官方定义才是"白物件 + 灰度明暗 + 黑轮廓"。于是换成 `Shaded` 母版 + `CustomLighting` + 自定义 albedo，做出三度灰阶：P10/P50/P90 = 101/119/152，跨度 51，纯白 0.00%。
- 阴影被关掉——`CustomLighting` 的方向光把地面阴影拉成大块深色椭圆，比无阴影更抢视线。v2.4 的"软阴影是主要好看来源"这个结论，换了光照方案后反转。
- 交互再收一刀：B 拾面原本必须 Ctrl+Shift 才能点到多重曲面上的单一面。查官方做法后把 `GeometryFilter` 从 `Surface|Brep` 改成只给 `Surface`，加 `DisablePreSelect()`，直接点哪取哪。
- 最后两套显示用结构线密度区分：浅色 0（仅边界）、深色 1（一条内部等参线），强制设置保证来回切换不残留。

四个阶段走完，基准面也完成了它的使命：从"能不能做"到"做得稳不稳"，再到"场景里跑不跑得动、看不看得清"。

## 三、观测显示：调参的账

显示这一层的作用，就是把基准面的结果真正呈现出来，让好坏一眼可见。

真正值得记的是**调参的开销**为什么高：

- **多轮参数扫描**：albedo、环境光、阴影强度、背景渐变、等参线颜色，每轮都要改一组参数、截图、对比。单 albedo 就扫了 4 组取值。
- **截图会骗人**：`CaptureToBitmap()` 返回缓存帧，只改 `DisplayMode` 不触发真正重绘。有几次几组不同参数的截图哈希和像素完全一样，差点得出错误结论。可靠的抓图流程是：置前窗口 + 相机微动 + `ZoomBoundingBox` + `Redraw()` + `Wait()` + sleep，每张图前重新置前。
- **判断必须定量**：不能靠"看起来差不多"。用逐像素统计算 P10/P50/P90 和 `clip(≥253)`，才有"跨度 51、纯白 0.00%"这种能复现的结论。

这直接影响了后期的优化方向——不是去砍效果，而是**把无效的调参花销挤掉**：先查资料确定技术路线（避免照抄错方案），再一次只改一个变量，测完当场删临时显示模式，不留下 `ZZ_*` 之类的垃圾在用户列表里。

## 四、小结

从零到一这条路，真正的主线只有一条：**先把基准面立住，再让每一次迭代都踩在它上面**。

- 阶段一解决"能不能跑"；
- 阶段二解决"可不可复现、能不能精确还原"；
- 阶段三走向真实场景，暴露了过曝与"照抄不等于好用"；
- 阶段四收口，用方向光三度灰阶和直接点面把效果、稳定性与易用性拉回平衡。

关于收益的部分这次没有放进来——它需要更扎实的数据支撑，等有了真实场景的量化结果，再单独成篇更合适。
