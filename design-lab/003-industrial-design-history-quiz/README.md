# 003 · 工业设计史每日闯关

> 单文件 HTML 答题程序：打开就能用，离线、无依赖、进度存本地。
> 题库来自本机 `D:/学习进步资料/工业设计史/` 的 DOC 资料，**每题可核对原文**。

## 1. 想法原话

> 「你调度百度网盘，然后搜索工业设计史，我里面有很多工业设计史的资料，
> 我想把那个设计成一些……类似于答题每日答题闯关的一些小程序，这样的话有助于去复习和温习」

## 2. 原理

复习类工具的关键不是"题多"，是**答错之后能回到原文**。所以本项目定三条：

1. **可追溯**：每题带 evidence，答错显示原文片段 + 来源文件名。没有原文的题不出。
2. **不编造**：构建时强制校验 evidence 前 12 字必须在源文件中命中，否则拒绝出题。
3. **确定性**：题目顺序用日期偏移的固定步长算（不用随机），同一天打开题目一致。

**技术选择**：单文件 HTML 而非微信小程序。理由：无需开发者工具编译、可直接双击打开、
方便你把题目文本拿去校对、离线可用、改动只是重新生成一个文件。
（用户拍板：单文件 HTML；题目范围：先用带答案的题库。）

## 3. 构造序列

```
D:/学习进步资料/工业设计史/【工业设计史】重点总结要点.doc  （UTF-16LE 老 DOC）
      │  Python 标准库按 utf-16le 解码 → 正则取连续中文段
      ▼
build_questions.py   FACTS 题卡（question/correct/wrong/evidence/topic）
      │  强制校验：evidence[:12] 必须在原文中 → 不过关就拒绝
      ▼
questions.json      11 道核实题（早期 5 / 工业革命 4 / 工艺美术 2）
      │  build_html.py 注入（唯一数据源，HTML 不手抄题目）
      ▼
quiz.html           单文件：每日 5 题 + 错题本 + 原文复习 + 连续天数
```

## 4. 落地形态

| 文件 | 作用 |
|---|---|
| `build_questions.py` | 题卡 + 原文校验，产出 questions.json |
| `questions.json` | 唯一题库数据源（每题含 evidence / source / topic） |
| `quiz.html.tpl` | 页面模板，含 `__QUIZ_DATA__` 占位符 |
| `build_html.py` | 把题库注入模板 → quiz.html |
| `quiz.html` | **最终交付**，单文件，双击即可用 |

功能：每日一关（5 题）、答错即时显示原文、错题本、答对移出错题本、
"再练一次"、"只看错题"、连续打卡天数、进度存 localStorage。

## 5. 证据

- 题库构建输出：`BUILT 11 verified questions`，TOPICS = 早期 5 / 工业革命 4 / 工艺美术 2。
- 首轮我曾手写 29 题，原文核对后**只有 11 题可追**，另外 18 题（包豪斯、现代主义、
  后现代、绿色设计等）是我凭通用知识写的、DOC 里没有 → **全部删除**。
  这是本项目最重要的一条记录：**宁可少，不可编**。
- HTML 生成 13.4 KB，`__QUIZ_DATA__` 占位符残留 0，`node --check` JS 语法通过。

**开放项**
- 题库只有 11 题、3 个主题，覆盖面不足。补题有两条路：
  ① 用户把题库 PDF 转成文字版（或提供可复制文本）；
  ② 用户允许联网/安装 OCR 后从扫描 PDF 提取。
  无论哪条，新题都必须过 `build_questions.py` 的原文校验。
