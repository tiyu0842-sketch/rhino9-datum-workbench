# Design Lab — 人与 AI 一起把想法落地

这里放的**不是教程，也不是成品**，而是"一个想法从嘴里说出来 → 变成能拖参数的几何 → 留下证据 → 下次能改"的完整轨迹。

为什么要这样组织（而不是散在聊天记录里）：

- 想法最怕丢。一句"我想要个渐变的东西"过三天就忘了当时的约束条件。
- 原理最怕重复讲。同一个原理讲第二遍就是纯浪费 token。
- 失败最怕重踩。踩过的坑不写下来，下次一定再踩一次。

## 一条想法走完的六步

| 步骤 | 产出 | 谁主导 |
|---|---|---|
| 1. 想法 | **原话**照抄，不改写、不美化 | 人 |
| 2. 原理 | 这件事在几何/数据层面到底发生了什么，引用出处 | AI 讲，人纠 |
| 3. 构造序列 | 意图 → 自由度 → 几何步骤 → 数据结构（各步输入输出类型与长度） | AI 起草，人改 |
| 4. 落地形态 | 选 GH 定义 / Rhino 脚本 / C# 插件，并写明为什么选它 | 一起定 |
| 5. 证据 | 实测数字（数量、抽样值）+ 截图 + 失败记录 | AI 实测 |
| 6. 复盘 | 哪里推翻了假设、下次怎么更快 | 一起写 |

**第 3 步写完，画布该怎么连基本就定了。** 跳过它直接连电池，是"结果不对但不知道为什么"的头号原因。

## 状态定义

| 状态 | 含义 |
|---|---|
| `设想` | 只有一句话，还没验证可行性 |
| `序列已设计` | 第 3 步完成，逻辑上通，还没搭 |
| `已搭通` | 真机搭出来了，求解无报错 |
| `已验证` | 数量/数值/视觉三件套都过 |
| `已发布` | 进了 yak 包 / GitHub release / Food4Rhino |

> 注意 `已搭通 ≠ 已验证`。GH 的 `solved=true` 只表示没抛异常，**不保证几何有效**（见 `001-gradient-boxes.md` 的退化盒）。

## 写新条目的方式

复制 `001-gradient-boxes.md` 的骨架，编号顺延。**不要省略第 5 步证据**——没有数字和截图的条目，一个月后自己都不敢信。
